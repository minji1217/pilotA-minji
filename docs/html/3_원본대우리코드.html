1·2번 식은 손실에만 쓰이나? 네. 우리 모델에서 1번(재해 발생, log p(z))과 2번(관측, log p(DPM | z))은 손실 계산에만 들어가고, 사후확률 q 자체는 3번 식(출발점 μ, flow, sigmoid)으로만 만들어집니다. 다만 학습 중에 1·2번이 든 손실을 줄이는 방향으로 3번 식의 숫자(a, c, δ, flow의 u · w · b)가 바뀌므로, 1·2번은 "q를 어느 쪽으로 움직일지 알려 주는 기준" 역할을 합니다. 학습이 끝난 뒤 결과를 낼 때는 3번 식만 씁니다 (256개 뽑아 평균). soft의 log(가능한 땅 비율)도 1번 식에 들어가므로 손실을 통해서만 영향을 줍니다. 원본은 1번 식의 w_a를 3번 식(μ = w_μ · w_a · α)에서도 써서, w_a가 손실과 q 계산 양쪽에 직접 들어간다는 점이 다릅니다.

학습은 1·2번 식(모델이 생각하는 세상)과 3번 식으로 만든 사후확률이 잘 맞도록 모든 숫자를 함께 조정합니다 (ELBO = 2번으로 DPM을 잘 설명하면서 1번 사전과 너무 멀어지지 않게). ⑤ 부호 제약은 1·2번 식의 w_a, w_x에 걸려 있고, ① μ 보정은 3번 식의 이야기입니다. 원본은 3번 식에서 w_a를 다시 쓰고(μ = w_μ × w_a × α), 우리는 3번 식에 전용 숫자 a를 둔다는 점만 다릅니다.

원본은 왜 양수로 제한하지 않았나

논문과 코드에 이유가 적혀 있지 않아 정확한 이유는 모릅니다. 원본 상황에서는 제한이 없어도 문제가 잘 생기지 않았을 이유는 있습니다 (추측).

  • 화소가 많음 (원본 자료 파일은 저장소에 없어 정확한 수는 모르고, 코드는 8,109개씩 묶어 여러 배치로 돌림): 줄이 몇십 개면 "DPM이 작은 곳이 재해"라는 거꾸로 된 답도 우연히 맞을 수 있지만, 화소가 많으면 USGS 확률이 높은 곳과 DPM이 큰 곳이 겹치는 경우가 많아 거꾸로 된 답이 대부분의 화소에서 맞지 않습니다.
  • 플러스에서 출발하고 조금만 움직임: 시작값이 0 ~ 1 난수(torch.rand)이고 lr 1e-5, 30 epoch라 부호가 넘어갈 만큼 움직이기 어렵습니다. 우리는 lr 0.01, 3000 epoch라 훨씬 많이 움직입니다.
  • triplet 벌점: "산사태 사후확률은 액상화 사전확률보다 산사태 사전확률에 더 가까워야 한다"는 벌점이 사후확률을 USGS와 같은 방향으로 끌어당깁니다 (우리 모델에도 있음).

그래서 원본은 제한 없이도 뒤집힐 가능성이 낮았고, 줄이 적고 학습이 긴 우리는 softplus로 방향만 고정했습니다.

칸 단위는? 칸 단위도 같은 모델 클래스(DisasterNet)를 써서 w_a, w_x가 softplus로 양수입니다. 칸 단위는 지진마다 4.5만 ~ 32만 칸으로 줄이 많아 "줄이 적어서"라는 이유는 약해지지만, lr 0.01 · 3000 epoch로 원본보다 훨씬 많이 움직이고 시정촌 실험과 같은 모델을 쓰려고 그대로 두었습니다. 칸 단위에서 이 제약을 뺀 실험은 없습니다.

원본 DisasterNet에서는 학습된 w_a, w_x가 양수였나

보장은 없습니다. 원본 코드에는 제한이 없고, 논문에 학습된 값이 나와 있지도 않습니다. 다만 (1) 시작값이 0~1 사이 난수라 모두 플러스에서 출발하고 (실행 스크립트의 미리 정한 값도 w_aLS = 0.4105, w_LSx = 0.2258처럼 모두 플러스), (2) 학습이 짧고(30 epoch, lr 1e-5) 조금씩만 움직이며, (3) 화소가 많아 (8,109개씩 여러 배치) USGS 확률과 DPM이 같이 큰 곳이 많아 거꾸로 된 답이 대부분의 화소에서 맞지 않으므로, 플러스로 남았을 가능성이 큽니다.

실제 예시모델에는 "USGS 사전확률이 높으면 재해가 더 잘 난다"(w_a)와 "재해가 나면 DPM이 커진다"(w_x)는 가중치가 있고, 둘 다 물리적으로 양수여야 합니다. 그런데 행이 적으면 거꾸로 된 해로도 DPM을 똑같이 잘 설명할 수 있습니다: w_x를 음수로 두고 DPM이 작은 시정촌을 "재해 남"으로 보는 해입니다. 이렇게 되면 사후확률 순서가 뒤집혀 AUC가 0.5보다 낮아집니다. 그래서 softplus(log(1 + e^x), 항상 양수)로 방향만 고정하고 크기는 학습하게 했습니다.

왜 바꿨나원본은 화소가 많아 (8,109개씩 여러 배치) 데이터가 방향을 잡아 줍니다: 재해 난 곳은 대부분 DPM이 크고 USGS 확률도 높아서, 뒤집힌 해는 수많은 화소에서 맞지 않아 자연스럽게 걸러집니다. 또 원본은 학습을 30 epoch만 하고 가중치가 0~1 난수(모두 양수)에서 시작해, 부호가 뒤집힐 만큼 멀리 움직이지 않습니다. 우리는 지진마다 시정촌 40~80곳으로 3000 epoch 학습하므로, 몇 곳만으로도 뒤집힌 해가 똑같이 잘 맞을 수 있고 학습이 길어 실제로 그쪽으로 갈 수 있습니다. 합성 데이터에서 제약 없이 두면 부호가 뒤집힌 해에 빠지는 것을 확인했습니다 (model.py 주석). 그래서 방향만 고정하고 크기는 학습합니다.

3. 자세히 1: 출발점 μ

8가지 차이 ①을 풀어 쓴 것. 바꾼 한 줄, 누가 같이 쓰나, a · c · δ가 각각 왜 있는지, 실제 학습된 값, 6·tanh 순서로 봅니다.

누가 같이 쓰나: 한 지진의 한 재해 안에서 하나

"모두 같이 씀"은 시정촌마다 하나씩이 아니라, 한 지진 안의 모든 시정촌(칸)이 값 하나를 같이 쓴다는 뜻입니다. 지진마다 모델을 처음부터 따로 학습하므로(pooled=False, 논문·공식 코드도 같음) 지진이 바뀌면 모든 값이 달라집니다.

왜 α 앞에 곱하는 수가 하나(a)뿐인가

원본 model.py
a1 = w_aLS * aLS          # 사전확률 식과 같이 쓰는 w_a
mu = w_mu_LS * a1         # μ = w_μ × w_a × α
# 사전확률 식: logit p = w_0 + w_a·α + …  (같은 w_a)
우리 model.py
self.mu = nn.Linear(1, 1)  # a·α + c (기울기 a, 절편 c)

# 사전확률 식의 w_a는 그 식에서 따로 학습

두 수를 곱한 것도 결국 숫자 하나입니다. w_μ = 5, w_a = 6이면 α 앞에는 30이 곱해지고, a = 30 하나로 쓴 것과 똑같습니다. 원본이 둘로 나눈 것은 w_a를 사전확률 식 logit p = w_0 + w_a·α + …와 같이 써서 출발점을 사전확률 식에 묶어 두었기 때문입니다. 논문은 출발점을 "부모 입력의 함수 μ = φ(부모; W_μ)"라고만 하고 사전확률 식과 묶으라는 말은 없어서, 우리는 출발점에 자기 기울기 a를 따로 주었습니다.

USGS 값을 넣는데 왜 USGS 근처에서 출발하지 않나

확률과 점수는 다른 눈금USGS α = 0.001은 확률 눈금의 숫자(0.1%)입니다. 출발점 μ = a·α + c는 점수(로짓) 눈금이고 나중에 sigmoid로 확률로 바꿉니다. 점수 눈금에서 0.001은 사실상 0이라 sigmoid(0.001) = 0.50입니다. 확률 0.001을 점수 자리에 그대로 넣으면 "0.1%"가 아니라 "50%"라는 뜻이 됩니다.

USGS 근처가 되려면확률을 점수로 바꾸는 logit(α) = log(α / (1 − α))를 넣어야 합니다 (sigmoid를 거꾸로 하는 식). logit(0.001) = −6.9이고 sigmoid(−6.9) = 0.001로 되돌아옵니다. α 대신 logit(α)를 넣으면 a = 1, c = 0일 때 출발점이 바로 USGS 확률이 됩니다.

지금은원본 공식 코드와 우리 코드 모두 α를 그대로 넣습니다 (사전확률 식 logit p = w_0 + w_a·α도 같음). 그래서 "c가 출발점을 내려 줘야 한다"는 얘기가 나왔고, 실제 학습된 c는 −0.8 ~ 1이라 출발 확률이 31% ~ 73%에 머물렀습니다.

해 볼 만한 아이디어출발점 입력을 logit(α)로 바꾸면 처음부터 USGS 근처에서 출발합니다. 논문 식에서 벗어나는 변경이라 하지 않기로 함 (10.21 결정: 원문처럼 α를 그대로 넣는 지금 방식 유지).

왜 c를 더하나: 직선의 기울기와 절편

μ = a·α + c 는 직선 y = ax + ba는 기울기, c는 절편(α = 0일 때의 높이)입니다.

c가 없으면 직선이 원점을 지남α = 0이면 μ = 0, 확률 0.5입니다. 그런데 칸 대부분의 α가 0 근처(산사태 중앙값 0.0007, 액상화 중앙값 0)라, 기울기 a를 어떻게 정해도 대부분 μ ≈ 0, 확률 0.5에 모입니다. USGS가 0.1%라고 하는 칸도 0.5%라고 하는 칸도 모델 안에서는 다 50% 근처에서 출발합니다.

c가 있으면 직선 전체를 내림기울기는 그대로라 α가 큰 칸이 더 높은 순서는 그대로이고, 전체 높이만 알맞게 내려갑니다. 알맞은 c는 학습이 찾습니다.

c는 누가 같이 쓰나한 지진, 한 재해 안의 모든 칸이 c 하나를 같이 씁니다. 산사태(c_LS)와 액상화(c_LQ)는 따로이고, 지진마다 모델을 따로 학습하니 지진끼리도 따로입니다. 칸마다 다른 것은 δ입니다.

flow가 있는데 왜 필요한가우리 flow는 점수를 최대 약 4까지만 옮길 수 있어서 0.5에서 출발하면 바닥이 1.8%입니다. 또 피해 없는 칸을 낮추느라 flow가 거의 모든 칸을 최대로 밀면 칸들이 바닥에 붙어 서로 구분할 여유가 없어집니다. c가 전체 높이를 잡고 flow는 칸마다 다듬는 쪽으로 역할이 나뉩니다. 다만 c가 꼭 필요한지는 c만 뺀 실험으로 아직 확인하지 않았습니다.

USGS 산사태 사전확률은 원래 작음시정촌이라서 작은 것이 아니라 USGS 산사태 확률 자체가 작습니다. 시정촌 산사태(평균) 중앙값 0.0009, 0.01 미만 92% · 칸 산사태 중앙값 0.0007, 0.01 미만 94%. 칸 액상화도 83%가 0.01 미만입니다 (시정촌 액상화는 최댓값으로 모아서 중앙값 0.23).

그래서 곱하기만 하면α가 거의 0이라 μ = (곱하는 수) × α도 거의 0이고, 출발 확률 sigmoid(0) = 0.5입니다. 그림 아래쪽처럼 구마모토 40곳 중 대부분이 0.5 근처에서 출발합니다. 실제로는 산사태가 난 시정촌보다 안 난 시정촌이 많아 0.5는 너무 높은 출발점입니다.

여기서 "출발 확률"이란우리 모델은 sigmoid를 flow 전에 쓰지 않고 맨 끝에 한 번만 씁니다. 출발점 μ는 점수(로짓)라 그대로는 감이 안 와서, "flow가 아무것도 안 했다면 끝의 sigmoid를 지나 확률이 얼마가 될까" = sigmoid(μ)로 바꿔 읽은 값입니다. 코드가 이 값을 따로 계산하지는 않습니다.

c를 더하면 (c = −3은 설명용, 실제 학습된 c는 아래 "실제로 학습된 a, c 값" 표)c는 출발점 전체를 위아래로 옮기는 수입니다. c = −3이면 α ≈ 0인 시정촌은 0.05 근처, α = 0.05인 시정촌은 0.18에서 출발합니다. 사전확률이 높을수록 출발점이 높은 순서는 그대로이고, 전체 높이만 옮겨 갑니다. 알맞은 c는 학습이 찾습니다. 다만 실제 학습된 c는 −0.8 ~ 1 정도라 이만큼 내려가지 않았습니다 (아래 "실제로 학습된 a, c 값").

c 없이도 되지 않나원본은 c 없이 출발점을 sigmoid로 0 ~ 1에 눌러 두고 flow 8단계(최대 8)로 옮깁니다. 우리는 flow가 4단계(최대 약 4)라 출발점 높이를 옮길 수단으로 c를 둡니다. 논문은 μ를 "부모 입력의 함수"라고만 해서, 곱하고 더하는 선형 함수는 그 범위 안의 기본 선택입니다. c가 꼭 필요한지는 c만 뺀 실험으로 확인해야 하고, 아직 하지 않았습니다.

왜 δ(self.mu_local)를 넣었나: 칸마다 자기 DPM을 출발점에 반영

δ가 없으면 같은 α는 같은 출발점공통 부분 a·α + c는 USGS 값 α만 봅니다. α가 같은 두 칸은 한 칸에 위성 피해 신호(DPM)가 크고 다른 칸에 없어도 출발점이 같습니다. 우리가 구하는 것은 "DPM을 보고 난 뒤"의 사후확률이라, 칸마다 자기 DPM에 따라 출발점이 달라져야 합니다.

δ = 칸마다 하나씩 있는 보정값코드의 self.mu_local이고 모두 0에서 시작합니다. 학습 중 손실의 관측식이 "이 칸의 DPM을 설명하려면 재해 확률이 더 높아야 한다"고 하면 올라가고, 반대면 내려갑니다. 자료가 근거를 줄 때만 움직입니다.

flow가 있는데 왜 또flow는 칸마다 밀 수 있지만 최대 약 4까지입니다. δ는 출발점 자체를 6·tanh 천장 안(−6 ~ 6)에서 옮겨 큰 이동을 맡고, flow는 세밀한 모양을 다듬습니다. flow 쪽에도 같은 이유로 칸별 보정값 flow_local이 있습니다.

원본은원본 출발점 μ = w_μ·w_a·α에는 칸별 보정이 없습니다. 대신 flow의 u, w, b를 만드는 Linear(N, K·N) 층의 가중치가 위치마다 따로 있어, flow 쪽에서는 사실상 칸별로 따로 움직입니다.

주의논문은 μ를 "부모 입력의 함수"라고만 해서 칸별 δ는 우리가 더한 것입니다 (c와 함께 "우리 판단"). δ는 DPM만 보고 학습하고 정답 라벨은 쓰지 않습니다. 칸마다 값이 하나씩이라 자료를 지나치게 따라갈 위험은 있고, 손실의 사전확률 항이 δ를 USGS 쪽으로 붙잡습니다. δ만 뺀 실험은 아직 없습니다.

원본은 왜 6·tanh가 필요 없었나
  • 이미 더 세게 눌러 두었기 때문: 원본은 flow 전에 sigmoid를 한 번 써서, μ가 얼마든 flow에 들어가는 값이 0 ~ 1입니다. 출발점이 극단으로 갈 수가 없으니 따로 천장을 둘 필요가 없습니다. (대신 모든 칸이 확률 0.50 ~ 0.73에서 출발하는 대가를 치름)
  • 커질 수 있는 값이 없었기 때문: 원본 μ = w_μ · w_a · α에는 칸마다 자유롭게 움직이는 값(δ)이 없고, α가 0.001 근처로 작아 μ도 거의 0입니다. 우리는 칸마다 δ가 있어 몇몇 칸의 δ가 계속 커질 수 있으므로 천장이 필요합니다.
  • 비유: 원본은 공(출발점)을 좁은 상자(0 ~ 1)에 넣어 두어 멀리 굴러갈 수 없고, 우리는 넓은 방(−6 ~ 6)에 풀어 두되 벽에 쿠션(부드러운 tanh)을 대 둔 것입니다.

"δ가 극단으로 갈 수 있다"는 게 무슨 뜻인가

  • 학습은 손실이 줄어드는 쪽으로 δ를 계속 민다: 어떤 칸의 DPM이 아주 크면, 관측식은 "이 칸은 재해 확률이 높을수록 DPM을 더 잘 설명한다"고 말합니다. 그래서 그 칸의 δ는 매 epoch 위로 밀립니다.
  • 거의 다 올라가도 멈추지 않는다: 출발점이 5(확률 0.993)에서 10(0.99995)으로 가면 확률은 거의 안 바뀌지만, 손실은 아주 조금이라도 줄어들어 같은 방향의 기울기가 남습니다.
  • Adam은 작은 기울기도 같은 보폭으로 움직인다: Adam은 기울기의 크기를 나눠 맞추기 때문에, 기울기가 작아도 방향이 일정하면 매번 대략 lr(0.01)만큼 움직입니다. 3,000 epoch이면 최대 약 0.01 × 3,000 = 30까지 갈 수 있습니다.
  • 그러면 생기는 문제: 출발점이 30이면 확률이 사실상 정확히 1이고, 그 근처에서는 flow도 사전확률 항도 그 칸을 거의 움직이지 못합니다 (기울기가 0에 가까움). 한 칸이 그렇게 굳으면 칸 최댓값으로 모으는 시정촌 점수도 그 칸에 끌려갑니다.
  • 6·tanh가 하는 일: δ가 얼마나 커지든 출발점은 6을 넘지 않습니다. 6 너머로는 기울기가 거의 0이라 δ가 더 커져도 출발점이 바뀌지 않으니, 극단으로 굳는 것을 막는 안전장치입니다.
  • 실제로는: 천장이 있는 상태에서 학습된 δ의 가장 큰 절댓값은 시정촌 모델에서 0.3 ~ 5.9였습니다 (오사카 액상화 seed 1이 5.92). 천장 없이 돌려 본 적은 없어서, 천장이 없었다면 실제로 얼마나 커졌을지는 모릅니다.

한 시정촌의 μ 계산 순서 (a = 30, c = −3, δ는 설명용, α는 あさぎり町 실제 값)

왜 ÷6, tanh, ×6인가tanh는 어떤 값이 들어와도 −1 ~ +1 사이로 내보내는 함수입니다. 0 근처에서는 들어온 값을 거의 그대로 내보내고(tanh(0.1) ≈ 0.0997), 값이 커질수록 ±1에 붙어 멈춥니다. 6으로 나눠 넣으면 웬만한 값은 0 근처라 거의 그대로 통과하고, 나온 값에 다시 6을 곱하면 원래 크기로 돌아옵니다. 결과적으로 보통 값은 거의 그대로(2는 1.93, −3은 −2.77), 아주 큰 값만 ±6에서 멈춥니다 (10은 5.59, 100은 6.00).

왜 하필 6인가μ는 로짓(확률을 펼친 값)입니다. sigmoid(6) = 0.9975, sigmoid(−6) = 0.0025라서 ±6이면 확률 0.25% ~ 99.75%를 다 쓸 수 있습니다. 더 넓혀도 확률은 거의 안 바뀌고, 좁히면 아주 확실한 곳(0.3% 미만, 99.7% 이상)을 표현하지 못합니다.

왜 묶나δ는 시정촌마다 따로 학습되는데 시정촌이 적으면 한 곳의 δ가 끝없이 커질 수 있습니다 (그 시정촌 DPM을 더 맞추려고 μ를 계속 밀어 올림). 묶어 두면 ±6 이상은 의미가 없으니 거기서 멈춥니다.

왜 tanh로 부드럽게"6보다 크면 6"처럼 딱 자르면 그 너머에서는 기울기가 0이 되어 학습이 멈추고 다시 돌아오지 못합니다. tanh는 끝까지 조금씩 기울어 있어 학습이 계속 움직일 수 있습니다.

왜 1이 아니라 0.99로 묶었나flow는 "되돌릴 수 있어야" 손실에 들어가는 log det(= log(1 + u × w × (1 − t²)))를 계산할 수 있습니다. u = 1, w = −1, t = 0이면 괄호 안이 0이 되고 log 0은 −∞라 학습이 깨집니다. 원본은 abs()를 씌워 숫자가 깨지지는 않게 했지만, 그 지점에서는 서로 다른 두 값이 같은 값으로 밀려 되돌릴 수 없습니다. 우리는 u, w를 0.99 안쪽에 두어 괄호 안이 항상 0보다 크게 했습니다. 최대 미는 양 1과 0.99의 차이는 결과에 거의 영향이 없습니다.

"flow를 되돌릴 수 있다"는 게 무슨 뜻인가 (그림)

  • 되돌릴 수 있다 = 민 뒤 값을 보고 밀기 전 값이 무엇이었는지 딱 하나로 알 수 있다는 뜻입니다. 그림에서 곡선이 오른쪽으로 갈수록 항상 올라가면 같은 높이에 점이 하나뿐이라 거꾸로 찾을 수 있습니다 (왼쪽).
  • 왜 필요한가: 손실에는 "밀면서 분포가 얼마나 늘어나거나 줄었나"를 재는 log det = log(곡선의 기울기)가 들어갑니다. 기울기가 0이면 log 0 = −∞라 계산이 깨지고, 기울기가 음수(거꾸로 감)면 확률 계산 자체가 틀립니다.
  • 한 층의 기울기 = 1 + u · w · (1 − tanh²). u · w가 −1보다 크면 항상 0보다 커서 곡선이 계속 올라갑니다.
  • 원본 (Hardtanh, ±1): u = 1, w = −1이면 u · w = −1이라 r = 0에서 기울기가 정확히 0 (갈색, 동그라미). 이 한 점에서 평평해집니다. 원본은 log 안에 절댓값을 씌워 계산이 멈추지 않게만 했습니다.
  • 묶지 않으면: u = 2, w = −2처럼 u · w < −1이면 가운데에서 곡선이 내려가, 같은 높이(점선)에 밀기 전 값이 셋이나 생깁니다 (빨강). 되돌릴 수 없습니다.
  • 우리 (0.99 · tanh): u, w가 최대 0.99라 u · w ≥ −0.98, 기울기가 항상 0.02 이상이라 곡선이 언제나 올라갑니다 (왼쪽 파랑). 원본과의 차이는 이 끝 한 점뿐이라 결과에는 거의 영향이 없습니다.

u, w, b는 어떻게 만드나: 원본 Linear(N, K·N) 대 우리 Linear(1, 3K) + 칸별 보정

원본 model.py (N = 배치 안 칸 수, K = 8)
amor_u = Sequential(Linear(N, K*N), Hardtanh(-1, 1))
amor_w = Sequential(Linear(N, K*N), Hardtanh(-1, 1))
amor_b = Sequential(Linear(N, K),   Hardtanh(-1, 1))

u = amor_u(a1).view(-1, K, N, 1)   # 배치 전체 α 벡터를 넣음
w = amor_w(a1).view(-1, K, 1, N)

amor = Linear(1, 3*K)                     # 칸 하나의 α로 12개를 만듦 (u, w, b × 4)

원본우리

한 번 미는 식z새 = z + u · tanh(wTz + b). wTz는 배치의 모든 칸 값을 섞은 숫자 하나라, 한 단계에서 모든 칸이 같은 tanh 값을 받고 칸마다 다른 것은 ui뿐r새 = r + u · tanh(w · r + b). 칸마다 자기 r, w, b로 tanh를 따로 계산 (논문 식 3)
최대로 미는 양한 번에 1, 8번이면 8한 번에 0.99, 4번이면 약 4

즉 둘 다 "칸마다 다르게 민다"는 점은 같지만, 원본은 거대한 층 하나가 배치 전체를 보고 칸마다 u를 정하고 tanh는 배치 전체가 공유하는 반면, 우리는 작은 공통 층과 칸별 보정으로 칸마다 u, w, b를 정하고 tanh도 칸마다 따로 계산합니다. 어떻게 미는지는 바로 아래 "flow는 어떻게 미나" 표에 4번 미는 실제 계산이 있습니다.

왜 우리는 Linear(N, K·N)을 안 썼나

  • 메모리: 가중치가 N × K × N개라 칸 수의 제곱으로 늘어납니다. 칸 단위(지진마다 4.5만 ~ 32만 칸)에서는 돌릴 수 없고, 원본 방식 칸 실험도 1,000칸씩 잘라 넣어야 했습니다 (orig_cells.py).
  • 칸끼리 섞임: 배치 안 모든 칸의 α를 한꺼번에 넣어 각 칸의 u, w를 만들기 때문에, 칸 A의 flow가 우연히 같은 배치에 들어간 먼 칸들의 USGS 값에 영향을 받습니다. 배치를 나누는 방식에 따라 결과가 달라질 수 있고 칸 수가 바뀌면 층을 새로 만들어야 합니다.
  • 논문 식: 논문은 u, w, b를 각 변수의 부모 입력(그 칸의 α)에서 만든다고 합니다. Linear(1, 12)는 그 칸의 α 하나만 보고 만들어 논문 식에 더 가깝습니다.
  • 대신 칸별 보정: Linear(N, K·N)이 하던 "칸마다 따로 움직이기"를 칸마다 13개(flow 보정 12개 + δ 1개)로 대신합니다. 이 칸별 값이 없으면 q가 α만의 함수가 되어, α가 같은 두 칸은 DPM이 달라도 같은 확률이 나옵니다.

원본은 flow 전에 sigmoid를 한 번 더, 우리는 논문 식대로 끝에 한 번만

원본 model.py (순서대로)
z = randn * std + mu      # 출발점 뽑기
z = sigmoid(z)            # ① flow 전에 sigmoid

    z = flow(z)           # 8번 밀기

논문 식 2–6 · 우리 model.py
r = mu + std * randn      # 출발점 뽑기 (r⁰ ~ N(μ, σ²))
for k in range(4):
    r = r + u * tanh(w*r + b)   # 4번 밀기
q = mean(sigmoid(r))      # 끝에 sigmoid 한 번

논문 식r⁰ ~ N(μ, σ²) 에서 뽑고, flow로 rK까지 민 뒤, q = sigmoid(rK)로 확률을 만듭니다. sigmoid는 맨 끝에 한 번만 있습니다. 우리는 이 식을 그대로 따랐고, 원본 코드의 ① 은 논문 식에 없는 단계입니다.

① 이 있으면 출발점이 0 ~ 1에 갇힘sigmoid는 무엇을 넣어도 0 ~ 1을 내보내니, μ가 얼마든 flow에 들어가는 값은 0 ~ 1입니다. flow가 아무것도 안 하면 끝의 sigmoid ② 를 지나 확률이 sigmoid(0) ~ sigmoid(1) = 0.50 ~ 0.73이 됩니다. 즉 원본은 모든 칸이 0.5 이상에서 출발하고, 낮은 확률은 전부 flow가 밀어 내려서 만들어야 합니다.

손실 계산도 앞뒤가 안 맞게 됨손실에는 "뽑은 출발값이 얼마나 그럴듯한가"를 재는 log q(r⁰) 항이 있고, 이 항은 출발값이 정규분포 N(μ, σ²)를 따른다고 보고 계산합니다. 원본은 sigmoid ① 을 거친 0 ~ 1 값을 넣어 이 항을 계산합니다 (log_normal_dist(z0, mu, …)의 z0가 sigmoid 뒤 값). 정규분포에서 뽑은 값과 sigmoid를 거친 값은 분포가 달라 이 항이 정확하지 않습니다. 우리는 sigmoid가 끝에만 있어 flow에 들어가는 값이 정말 정규분포에서 뽑은 값이고, 손실 식이 논문대로 맞습니다.

우리는 출발점이 곧 로짓μ가 그대로 로짓이라 μ = −5면 확률 0.007, μ = 0이면 0.5, μ = 5면 0.993에서 출발합니다. 출발점부터 낮은 곳, 높은 곳에 놓을 수 있고 flow는 칸마다 ±4 안에서 다듬습니다.

  • "sigmoid는 우리도 씁니다. 논문 식대로 flow가 끝난 뒤 맨 마지막에 한 번 씁니다 (q = sigmoid(rK), 식 2–6). 원본 코드는 flow 전에 한 번 더 쓰는데, 이 단계는 논문 식에 없습니다."

8개 뽑으면 r⁰를 평균내나: 아니요, 확률을 평균냄

8개를 각각 끝까지 계산ε을 8개 뽑아 r⁰도 8개가 생기고, 8개가 각자 flow 4번을 지나고 각자 sigmoid로 확률이 됩니다. 마지막에 그 8개 확률을 평균낸 것이 q입니다. r⁰를 먼저 평균내지 않습니다.

왜 순서가 중요한가sigmoid는 곧은 직선이 아니라 휘어 있어서, "평균을 내고 확률로 바꾼 값"과 "확률로 바꾸고 평균낸 값"이 다릅니다. 오른쪽 예에서 r⁰ 평균 −2.06을 확률로 바꾸면 0.113이지만, 8개를 각각 확률로 바꿔 평균내면 0.145입니다. 논문 식 6의 사후확률 q = E[sigmoid(r)]는 뒤쪽(확률의 평균)입니다.

학습 중에도 같음손실의 각 항(관측식, 사전확률 항, log q)도 8개마다 따로 계산한 뒤 평균냅니다. 마지막 결과는 같은 방식으로 256개입니다.

6. 자세히 4: 관측값 DPM (+2와 배경 빼기)

8가지 차이 ⑥을 풀어 쓴 것. 음수가 생기는 이유, 칸 단위에서도 배경을 빼는 이유, 원문과의 차이 순서입니다.

DPM에 왜 음수가 생기나: 화소 크기가 아니라 배경(프레임 중앙값) 빼기칸마다 프레임을 하나만 써도 배경 빼기가 필요한 이유원문은 배경을 빼지 않고 어떻게 했나: ARIA DPM을 그대로

DPM에 왜 음수가 생기나: 화소 크기가 아니라 배경(프레임 중앙값) 빼기

  • 화소 크기는 원인이 아님: 40 m 화소를 250 m 칸(또는 시정촌)으로 평균내는 것(②)은 양수들의 평균이라 거의 양수로 남습니다.
  • 음수가 생기는 곳은 ③: 한 지진의 시정촌(칸)들은 서로 다른 위성 프레임·궤도로 덮입니다 (전체 16프레임, 시정촌마다 가장 많이 덮는 궤도 하나를 쓰고, 같은 궤도 프레임이 겹치면 합성). 프레임마다 촬영 시기·조건이 달라 전체 상관도 수준이 다르기 때문에, 그대로 두면 "어느 프레임에 찍혔나"가 DPM 크기를 좌우합니다. 그래서 프레임별로 그 프레임 전체의 중앙값을 빼서 기준을 맞춘 뒤(DPM_배경차 = 칸 평균 − 프레임 중앙값) 시정촌·칸 값으로 합칩니다. 중앙값을 빼면 중앙값보다 덜 변한 칸은 음수가 되어, 칸 41%, 시정촌 35%(264곳 중 92곳)가 음수입니다.
  • 그래서 +2: log는 음수에 쓸 수 없어 모든 칸에 2를 더합니다. 상관도는 0 ~ 1이라 DPM(상관도 차이)은 −1 ~ 1, 중앙값을 빼면 이론상 −2 ~ 2라서 2를 더하면 항상 0 이상이 됩니다 (실제 가장 작은 값은 −0.763). 1을 더해도 전체 AUC 차이는 0.002였습니다. 모두에 같은 수를 더하니 칸끼리의 순서는 그대로입니다. 원본은 배경을 빼지 않은 ARIA DPM이라 처음부터 양수입니다.

칸마다 프레임을 하나만 써도 배경 빼기가 필요한 이유

  • 문제는 칸 안이 아니라 칸과 칸 사이: 칸 A, B는 각자 프레임 하나만 씁니다. 그래도 A는 프레임 1, B는 프레임 2라서, 두 프레임의 전체 수준(중앙값 0.30 대 0.10)이 다르면 같은 피해라도 A가 B보다 크게 보입니다.
  • 모델은 지진 하나의 모든 칸을 같이 학습하므로, 이대로면 "A 쪽이 피해가 크다"고 잘못 배웁니다. 각자 자기 프레임 중앙값을 빼면 둘 다 0.10으로 맞춰집니다.
  • 비유: 0점이 다른 체중계 두 대. 한 사람이 한 대만 써도, 두 대로 잰 사람들끼리 비교하려면 0점을 맞춰야 합니다.
  • 배경을 안 빼려면: (1) 프레임마다 모델을 따로 학습하거나, (2) 관측식의 기본값 w_0x를 프레임마다 따로 두어 모델이 차이를 흡수하게 하는 방법이 있습니다 (둘 다 아직 안 해 봄). 그래도 DPM(상관도 차이)은 원래 −1 ~ 1이라 음수가 남을 수 있어 log에는 여전히 더하는 수가 필요할 수 있습니다.

주의: 6·tanh는 값을 0 ~ 1로 "퍼지게" 하는 장치가 아닙니다. 점수의 바깥 한계만 정하고, 그 안의 보통 값(−3 ~ 3)은 거의 그대로 둡니다. 확률(0 ~ 1)로 바꾸는 것은 맨 끝의 sigmoid입니다.
